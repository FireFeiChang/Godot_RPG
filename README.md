# Test-ARPG

> **v1.8** ｜ 2D 像素风动作角色扮演游戏（ARPG）｜ Godot 4.7（Forward Plus 渲染）

一款以 **Heartbeast 的 "Action RPG"** 教程为基础、用 Godot 4.x 重制并大幅扩展的竖版视角 2D 像素 ARPG。玩家在田园村庄与树林间冒险：采集草药、挥剑击退蝙蝠与橡子甲虫、开宝箱收集 RPG 道具、攒金币、与村长对话接取并交付任务、管理背包。

## 游戏简介

村庄外的树林里蝙蝠泛滥，扰得村民无法下地劳作。玩家从村口出发，探索一张**重制过的田园大地图**：砍伐/采集途中收集**草丛**止血、消灭**蝙蝠**获取材料，并向村口的**村长**接取"消灭蝙蝠"的任务——完成后再回到村长处交付，换取奖励。

- **玩法类型**：俯视角 2D 动作角色扮演
- **画面风格**：像素风，320×180 逻辑分辨率放大至 1280×720
- **当前版本**：v1.8 —— 3 张地图、3 条任务线（6 个任务）、小地图、常驻 HUD

## 功能特性

### 战斗与角色
- **三态动作状态机**：移动（MOVE）/ 翻滚闪避（ROLL，带无敌帧）/ 攻击（ATTACK，硬直）。
- **模块化碰撞盒系统**：攻击判定 `HitBox` 与受伤判定 `HurtBox` 分离；受击后触发**无敌帧 + 闪烁动画**（白色闪白 shader）。
- **击退反馈**：攻击命中与受击均带击退方向，手感清晰。
- **生命值系统**：心形 HUD 实时显示血量；可被草丛（治疗）恢复。

### 敌人与 AI
- **蝙蝠敌人**：`待机 / 漫游 / 追击` 三态 AI，自动索敌、软碰撞防堆叠；死亡掉落**蝙蝠材料**与金币。
- **橡子甲虫**：`待机 / 漫游 / 滚球攻击` 三态 AI——发现玩家即卷成球正面滚向玩家冲撞；死亡先播死亡动画，播完才爆炸掉落。
- **哥布林**：`待机 / 漫游 / 追击` 三态 AI，地面近战敌人，发现玩家即挥击追击。
- **宝箱怪（Mimic）**：平时**伪装成物件静止**，玩家靠近才苏醒追击；死亡爆炸掉落。
- **史莱姆**：`待机 / 漫游 / 追击` 三态 AI，缓慢弹跳接近玩家后攻击。
- 以上三种新敌人共用通用 `Mob` 基类（`Enemies/mob.gd`），通过 sheet 横条图 + 帧数配置差异化；死亡统一走「播完 Death 动画 → 爆炸 → 掉落 → 销毁」流程。

### 小地图
- **右上角常驻小地图**：显示可行走区、泥路、崖壁轮廓、**关口**与玩家位置（白点实时跟随）。
- 数据**实时取自地图**（`CliffTileMap` / `DirtPathTileMap` / `EdgeTriggers`），地图改了它自动同步，无需重新烘焙。
- 面板尺寸随地图大小变化；底部标有当前地图名。地图外（主菜单）随 HUD 一起隐藏。

### 世界与探索
- **全新重制的田园大地图**（约 800×600）：草地 + 泥路村道 + 灌木/树/草丛 + 峭壁山岩围合边界，无虚空、无贴图发虚。
- 左下方**安全出生村口**；相机平滑跟随，可完整探索全图。
- **可采集草丛**：攻击草丛掉落可治疗物品。
- **世界宝箱（6 个）**：地图各处分布银箱，挥剑开启 → 开箱动画 → 扇形掉出该档掉落池的 RPG 道具（拾取入包）。
- **金币掉落**：击杀敌人掉落金币，HUD 右上角实时显示余额。
- 蒸汽通风口等环境装饰点缀地图。

### NPC 与对话（Dialogue Manager 插件）
- 靠近 NPC 显示交互提示，按 `回车` 触发多分支对话。
- **可扩展 NPC 架构**：普通闲聊 NPC 与**任务 NPC**（村长）共用一套基类，新增 NPC 复制即用。

### 任务系统
- **3 条任务线、共 6 个任务**，由 2 位 NPC **串行发布**（一次一条，交付领奖后解锁下一条）：
  - **村庄保卫线**（村长，村口田野）：消灭蝙蝠 ×5 → 采集止血草 ×10 → 消灭橡子甲虫 ×3
  - **东原探险线**（东原冒险者，东原营地）：消灭史莱姆 ×3 → 消灭哥布林 ×3 → 开启宝箱 ×3
- **先打的怪也算数**：进度由全局累计账本记录，接任务时会自动补记 —— 不必担心先清怪导致任务做不完。
- 每条任务有 4 段状态对话（未接 / 进行中 / 可交付 / 已领奖），接取时可选择拒绝。

- **任务由 NPC 发布与交付**：NPC 按玩家当前进度自动切换对话——*未接（可接取）→ 进行中（提示进度）→ 已完成（交付领奖）→ 已领奖（还有后续）*。
- **按 `Q` 弹出任务列表**，实时查看进行中目标与可交付任务。

### 背包与物品
- **30 格背包**（6×5 界面），支持**采集 / 击杀掉落 / 开宝箱 / 任务奖励**入包。
- 物品类型：`HEAL 治疗` / `MATERIAL 材料` / `KEY 钥匙`。
- 治疗类物品（草丛）可恢复生命，生命满时不可浪费。
- 另有 **16 件 RPG 收藏道具**（背包/帐篷/火把/宝石/罗盘/地图/钥匙等）与 **金币钱包**（见下）。

### 开局的干净体验
- **每次开始都是一局全新的游戏**：点"开始"即清档进入，血量、背包、任务全部重置，不继承上一局；自动存档已停用。适合快速反复试玩与开发调试。

### 界面与音频
- 生命值 HUD、物品计数器、任务列表弹层。
- 标题界面（开始 / 设置 / 退出）+ 音量调节；击中/受伤/翻滚/死亡等音效。

## 核心玩法循环

```
前往村长接取任务（消灭蝙蝠）
        │
        ▼
   探索地图 → 攻击草丛采集（补血）＋ 消灭蝙蝠（计数）
        │
        ▼
   达成目标（5/5）→ 任务完成
        │
        ▼
   回村长处对话交付 → 领取奖励（蝙蝠材料×3）入包
```

## 系统架构

### 全局自动加载（Autoload）

| 名称 | 来源 | 职责 |
| --- | --- | --- |
| `PlayerStates` | `Player/player_states.tscn` | 全局玩家生命值（`health`/`max_health` + 信号） |
| `Dialog` | `Player/dialog.gd` | 对话/任务握手的全局标志位（对话冻结、任务接/交请求） |
| `TaskManager` | `tasks/task_manager.tscn` | 任务注册、**累计账本**、目标事件路由、任务链推进、接取/交付、掉落物生成 |
| `SaveManager` | `save/save_manager.tscn` | 存档读写（v1.1 起默认清档新开局，存档框架保留） |
| `Inventory` | `inventory/inventory_manager.gd` | 全局背包唯一数据源 + 物品注册表 |
| `Wallet` | `coins/wallet.gd` | 金币余额全局钱包 + 世界金币掉落生成 |
| `DialogueManager` | Dialogue Manager 插件 | 第三方对话引擎 |

### 关键设计约定

- **伤害路由按脚本文件名匹配**（脚本路径含 `hit_box` 才会造成伤害），新增伤害盒必须遵守。
- **玩家剑/草地/宝箱判定**：玩家 `SwordHitBox` 位于 layer **8**（未在 1-7 命名层），草丛/宝箱 HurtBox 以 `collision_mask=8` 接收；收到后按上方"脚本名含 hit_box"路由。
- **动作硬直态**由 `AnimationPlayer` 方法轨道回调（`attack_animation_finished()` / `roll_animation_finished()`）在动画末尾触发复位。
- **NPC 任务对话分派**：NPC 脚本按 `TaskManager` 中任务状态选择对话标题（`<任务id>_offer/_in_progress/_turnin/_rewarded`），`.dialogue` 内仅用 `set` 突变向 `Dialog` 写入"请求接/交"标记，由 NPC 每帧消费后真正操作任务——对话文件与玩法逻辑解耦，无需在脚本里写解析依赖。
- ⚠️ **对话标题写错是静默失败**：`start_dialogue()` 找不到标题会退回 `start_title`，于是 NPC 只会说 `hello`、任务永远接不到。新增任务链后要逐个核对 4 个标题都存在。
- **任务目标由数据驱动**：目标字典里的 `source`（`kill:种类` / `collect:物品id` / `open:chest`）决定它由哪种事件推进。**新增任务只需写 `.tres` + 登记进 `DEFAULT_TASKS`，不用改任何代码**。没有 `source` 的目标永远不会自动推进。
- **累计账本让任务不会死**：敌人不重生，进度若只在接取后才累加，先清怪的玩家就永远做不完。账本记录全局累计（与接没接任务无关），接取时补记，所以"先打的也算数"。
- **HUD 输入守卫查祖先不查自己**：`is_visible_in_tree()` 含节点自身的 `visible`，面板 `_ready()` 里调了 `close()` 就会让守卫永远 return、面板再也打不开。用 `_ancestors_visible()`，且要**同时判 `CanvasItem` 与 `CanvasLayer`**（后者不是前者）。

## 运行方式

1. 安装 **Godot Engine 4.7**（需支持 Forward Plus / Vulkan）。
2. 在 Godot 项目管理器中**导入**本目录，或直接用 Godot 打开 `project.godot`。
3. 运行主场景 `UI/main_menu.tscn`（默认主场景）。
4. 点击"开始"即可进入 `world.tscn` 开始全新一局；走到地图边缘的关口会自动切换到相邻地图。

> 直接运行任意一张地图（`world.tscn` / `maps/map_north.tscn` / `maps/map_east.tscn`）也可 ——
> 会跳过主菜单、同样触发开局重置。

## 技术要点

- **纯编辑器驱动工程**：无测试套件 / linter / CLI 构建，以 `.tscn` 场景 + `.gd` 脚本为主。
- **资源即数据**：物品、任务均以 `Resource`（`.tres`）定义，便于在编辑器中配置与扩展。
- **UID 引用**：场景/脚本间大量以 `uid://…` 相互引用，重命名或移动文件时需保留 `.uid` 伴随文件。
- **ui_accept / attack 等输入**可在 `project.godot` 的 `[input]` 中按需增改。
